# 📋 任务规划与节点目标

## 一、总体目标

GitHub 仓库化收尾：元信息与标签体系落地、Pages 自动部署全链路闭环、远程 main 同步。

## 二、任务分解

### Task 1: 仓库元信息与标签/关键词设计 ✅
**验收标准**:
- [x] package.json：repository/homepage 指向 GitHub 主仓与 Pages 线上地址
- [x] keywords 20 项与 README Topics 表、GitHub Topics 三处同源
- [x] GitHub 平台侧写入 description + 20 项 Topics（gh api）
- [x] README 增加仓库信息表 + CI/Pages 徽章

### Task 2: Pages 部署设计与 CI 完善 ✅
**验收标准**:
- [x] deploy-pages 作业：needs 质量门禁、仅 push main、OIDC 零密钥
- [x] 产物检测：CNAME/index.html/manifest/sw.js/favicon 存在且非空 + 无 noindex
- [x] configure-pages 自愈启用 + concurrency 部署互斥
- [x] site.json robots.index 修正为 true
- [x] README 部署设计章节（链路图 + 设计项表）

### Task 3: 本地全量验证 ✅
**验收标准**:
- [x] typecheck 0 error · lint 0 error · knip 0 issue · madge 0 circular
- [x] vitest 130/130 通过
- [x] build 通过且 dist 五项产物检测与 CI 同口径复验通过

### Task 4: 提交并同步远程 main 🔄
**验收标准**:
- [ ] 会话文档入库
- [ ] 提交（含 README.md 未提交改动与 public/CNAME）
- [ ] 推送 github main（策略待用户确认：远端分叉需 force-with-lease）
- [ ] CI 首跑全绿 + Pages 部署成功（gh run 监控）

## 三、风险点

| 风险 | 应对 |
| ---- | ---- |
| force push 覆盖 main | git cherry 已验证远端无独有内容；使用 --force-with-lease 防竞态 |
| 首次 Actions 运行未知失败 | gh run watch 实时监控，失败即修 |
