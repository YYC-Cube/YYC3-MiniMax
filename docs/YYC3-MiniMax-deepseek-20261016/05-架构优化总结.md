# 🏛 架构优化总结：8 Agent 与 ReAct-C 九步闭环解耦

> 一句话：编排核从 UI 中抽离为纯核（core/），UI 只发命令、worker 执行、事件回流，
> 模型/工具全走端口（ports）与可替换适配器（adapters），全链留痕、失败可重试/回滚/人工接管。

## 一、背景与目标

迁移后的指挥中心（Next.js 16 静态导出）中，8 Agent 与 ReAct-C 九步闭环原本内嵌于 UI
演示层（setTimeout 假回复、无真实状态机）。本季优化目标：

1. `agent-orchestrator` 不依赖 UI、不依赖 Next.js
2. 每个 Agent 统一六元组接口：input / context / tools / output / trace / error
3. 九步以纯函数状态机实现；Step7 不达标回环 Step5，复检 ≤2 轮
4. 任务队列与 Agent 解耦：UI 只发命令，worker 执行，事件回流
5. 所有 Agent 调用走 ports；适配器可替换 local / vLLM / Registry
6. 全链留痕：traceId、耗时、Token、模型名、风险标签
7. 失败可重试、可回滚、可人工接管
8. 禁止 Agent 直接操作 DOM / localStorage / fetch

## 三、目标架构映射与依赖方向

目标图为 monorepo 包结构（packages/*+ apps/*）；本仓为单包分层，边界语义等价、
物理隔离由 depcruise + eslint 双守卫承担：

| 目标包 | 本仓物理位置 |
| -------- | ------------- |
| packages/contracts | `src/types`（纯核：不依赖任何业务包） |
| packages/application | `src/workers/orchestratorClient.ts`（门面）+ `src/core/runtime` |
| packages/domain-* | `src/core/machine` + `src/core/agents` + `src/domain` |
| application/ports | `src/types/ports.ts` |
| packages/adapters-* | `src/services/adapters` |
| packages/task-queue | `src/core/queue` |
| packages/agent-orchestrator | `src/core`（agents/machine/queue/runtime） |
| packages/observability | `src/workers/observability` + `src/services/telemetry` |
| apps/worker | `src/workers/orchestratorWorker(.entry).ts` |
| apps/web · features | `src/app` + `views` + `components` + `hooks` + `context` |

依赖方向规则 **7/7 达标**（详见 [04-目标架构可视化与依赖规则核验](./04-目标架构可视化与依赖规则核验.md)）：
UI→application→domain ✅ / adapters→ports←application ✅ / contracts 零业务依赖 ✅ /
domain 无框架无平台 API ✅（crypto 特性检测豁免留痕）/ orchestrator·task-queue 不依赖 UI ✅ /
observability 横切注入 ✅。守卫规则 13 条全部 error 级（[.dependency-cruiser.cjs](file:///Users/yanyu/YYC-Cube/YYC3-MiniMax/.dependency-cruiser.cjs)），
其中 `ui-only-orchestrator-client` 为目标架构对齐时新增——UI 对 workers 仅放行 client 门面。

## 五、关键决策

| 决策 | 理由 |
| ------ | ------ |
| 增量抽核而非重写 | 仓内已有 ports 雏形，保留契约测试资产，零回归 |
| worker/进程内双模式 | vitest 无法加载 worker chunk；与 eventStream LIVE/SIM 降级哲学同构，语义一致 |
| 状态机效应描述符化 | `reduceReAct` 零 IO，可观测/副作用由 runtime 翻译——核可移植至 Node/Worker |
| crypto 特性检测而非 import | 核内禁 services 依赖；uuid 需三端（DOM/Worker/Node）同构 |
| 覆盖率补测试而非降阈值 | 预算/棘轮类门禁禁止放宽绕过 |

## 六、风险与后续

| 项 | 等级 | 说明 |
| ---- | ------ | ------ |
| Lighthouse 实数 | P2 | 本地无 headless Chrome 未跑；推 GitHub 后以 CI `lighthouse` job 报告为准 |
| 备用镜像 | 已清理 | 镜像计划已撤销，相关远程配置与记录已移除（仅保留 GitHub 主仓单远程） |
| crypto 豁免 | 记录 | 特性检测+回退，非平台绑定；若未来迁移 Node 专用核可改 `node:crypto` 注入 |
| S7 解析降级语义 | 观察项 | score 解析失败按「门禁不可评估→通过」处理，由遥测 `audit.react.terminal` 旁证，后续可收紧 |

## 七、回滚方案（可执行）

- **代码回滚**：主线收敛为单提交序列，`git revert <commit>` 即可整体回退架构解耦
  （UI 回归 setTimeout 演示态；depcruise/eslint 规则随 revert 一并移除，无残留半态）。
- **运行时回退**：双模式设计使 Worker 不可用时自动进程内运行；模型适配器配置不合法
  自动降级 mock 并结构化告警——无需代码变更即可回退运行形态。
- **人工接管兜底**：生产任务异常经 TakeoverCard `abort` 终结（failed 审计留痕），会话
  检查点保留至终态清理，无悬挂状态。
